Roadmap / Web foundations

TRACK 01 / START HERE

Build your web foundations.

Before building an app, learn what happens when a browser requests a page, how to work with files and Git, and how to break a problem into steps a program can follow. Work through these four lessons in order and try each activity as you go.

4 lessonsBeginner friendlyLearn by doing
LESSON 01

How the web works

A web page is delivered through a conversation between a client and a server. Your browser is the client: it asks for a resource. A server receives that request and sends back a response, often containing HTML, CSS, JavaScript, or data.

From a URL to a page

  1. You enter a URL such as https://example.com/products. The browser uses DNS to find the network address associated with the domain name.
  2. For an HTTPS site, the browser establishes an encrypted connection with the server.
  3. The browser sends an HTTP request. The method describes the action: GET asks to read something; POST commonly sends new information.
  4. The server responds with a status code and content. For example, 200 means the request succeeded, 404 means the resource was not found, and 500 indicates a server error.
  5. The browser reads the returned files, requests any referenced assets, and renders the page.
Keep the layers straight: DNS helps locate a server; HTTP defines the request and response; HTML, CSS, and JavaScript define the page the browser displays.

Try it

Open your browser’s developer tools and select the Network panel. Reload a page, choose its document request, and identify the request method, status code, and response type. Notice that one page load usually makes many requests for images, stylesheets, and scripts.

LESSON 02

Command line & Git

The command line lets you navigate folders and run development tools. Git records changes to your project so you can review your work and return to earlier versions. A Git repository is the project history stored alongside your files.

A small Git workflow

Run these commands from your project folder. Git may ask you to configure your name and email the first time you commit.

git init
git status
git add index.html
git commit -m "Add the home page"
git log --oneline
  • git init starts tracking the folder as a repository.
  • git status shows which files are changed and whether they are staged.
  • git add stages the specific changes you intend to save.
  • git commit creates a named snapshot of the staged changes.
  • git log shows the snapshots already recorded.
A commit is a checkpoint, not a backup service. Make focused commits with clear messages, and keep a separate backup or remote repository for important work.

Try it

Create a project folder, initialize Git, add a short README, and commit it. Change one sentence, run git status, then stage and commit the update. Compare the two entries in git log.

LESSON 03

Programming fundamentals

Programs turn instructions and data into results. Most everyday code is built from a few reusable ideas: values, variables, decisions, repetition, functions, and data structures.

  • Values and variables: values are pieces of data; a variable gives a value a name you can use later.
  • Conditions: an if statement chooses what to do based on whether a condition is true.
  • Loops: loops repeat work for a collection or until a condition changes.
  • Functions: functions package a task behind a name, accept inputs, and can return a result.
  • Collections: arrays hold ordered items; objects group related values under named properties.
const prices = [12, 8, 15];

function totalWithTax(items, taxRate) {
  const subtotal = items.reduce((sum, price) => sum + price, 0);
  return subtotal * (1 + taxRate);
}

const total = totalWithTax(prices, 0.1);
if (total > 30) {
  console.log("The order is over 30");
}

Here, prices is an array, totalWithTax is a function, and if makes a decision using the returned number. Breaking the work into named steps makes it easier to understand and test.

Try it

Add another price to the array. Change the tax rate and check the result. Then write a function that returns the largest number in an array, and test it with an empty array as well as a few numbers.

LESSON 04

Developer workflow

A dependable workflow is a repeatable loop: understand the task, make one small change, run the project, check the result, and save a useful checkpoint. Small steps make mistakes easier to find.

  1. Understand: describe what should happen and how you will tell when it works.
  2. Inspect: read the relevant files and check the current behavior before editing.
  3. Change: make one focused improvement rather than several unrelated changes at once.
  4. Verify: run the app and check the important paths. Read error messages and use browser developer tools to inspect console and network failures.
  5. Review and save: inspect the diff, remove accidental changes, then commit with a message describing the result.

Debug with evidence

When something breaks, reproduce it consistently, read the first relevant error, and narrow down where the observed result diverges from what you expected. Check one cause at a time, then repeat the same test after making a fix.

Good habit: write down the steps to reproduce a bug. A clear reproduction is useful to you, your teammates, and anyone reviewing the fix.

Try it

Choose a small change in your project. Write down its expected result, implement it, test it in the browser, and review the Git diff before committing. If you find a problem, record the reproduction steps and investigate one hypothesis at a time.

YOU’RE READY FOR WHAT’S NEXT

Put the foundations together

You have now traced a request from browser to server, practiced recording project changes, used core programming concepts, and followed a repeatable build-and-check workflow. Apply them together: make a small page, inspect its requests, change it in a focused step, and commit the result.
